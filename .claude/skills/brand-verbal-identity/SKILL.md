# Brand Verbal Identity — como a marca fala, de um jeito que qualquer squad consegue repetir

Guia de voz que só diz "somos próximos e confiantes" não guia ninguém. Identidade verbal útil é **operacional**: cada dimensão de tom tem posição numa escala, exemplo do que dizemos e do que não dizemos, e um contexto onde se aplica. E cada frase rastreia à plataforma — voz é a personalidade (§3) falando, não uma personalidade nova.

## 1. Regra de rastreio

Toda seção do guia cita a seção da plataforma que a sustenta (`↳ plataforma §3 traço "direta"`). Se uma frase precisa de um atributo que não está na plataforma, ela não entra: vira sugestão à strategist. Promessa, prova e público são da plataforma; como se diz é seu.

## 2. Opções de direção (antes do guia)

Sempre **2–3 direções**, curtas, para a strategist escolher por contraste. Cada direção: 3–5 dimensões com posição, 1 parágrafo de manifesto-teste, 2 taglines-teste, tabela "traço da plataforma → como aparece nesta direção", e "de que concorrente esta direção se afasta" (mapa de territórios). Direção única não é escolha.

## 3. Dimensões de tom

Escolha 4–6 dimensões relevantes para a marca e posicione cada uma numa escala de 5 pontos, com exemplo nos dois extremos e na posição escolhida:

| Dimensão | ← 1 | 2 | 3 | 4 | 5 → | Posição | Exemplo na posição |
|---|---|---|---|---|---|---|---|
| Direto ↔ Elaborado | | | | | | 2 | "Você paga uma vez. Pronto." |
| Sério ↔ Bem-humorado | | | | | | | |
| Técnico ↔ Cotidiano | | | | | | | |
| Íntimo ↔ Institucional | | | | | | | |
| Afirmativo ↔ Provocador | | | | | | | |

Dimensões comuns: formalidade, densidade, temperatura (calor/frieza), energia, humor, certeza. Posição vem do traço "é / não é" da plataforma — cite.

## 4. Dizemos / não dizemos

Por dimensão **e** por contexto:

| Contexto | Dizemos | Não dizemos | Por quê (traço) |
|---|---|---|---|
| Site — hero | | | |
| Social — legenda | | | |
| Venda — proposta | | | |
| Suporte — resposta a problema | | | |
| Erro / mensagem de sistema | | | |
| Institucional — sobre | | | |

Mínimo 3 pares por contexto. "Não dizemos" inclui o que o concorrente diz e a marca recusa (postura §6).

## 5. Framework de mensagens

Por **público prioritário** (plataforma §1):

```
Promessa (plataforma §3)
 ├─ Pilar 1 — prova(s) com fonte (§5 / SIRIUS) — mensagem por nível
 ├─ Pilar 2 — …
 └─ Pilar 3 — …
```

Níveis de consciência: não sabe que tem o problema · sabe do problema · conhece soluções · conhece a marca · pronto para agir. Uma mensagem por pilar por nível. Número só com `#id` FECHADO da ficha de VEGA; citação de público só das coletadas por SIRIUS.

## 6. Manifesto

Um texto de 120–220 palavras que alguém lê em voz alta sem tropeçar. Estrutura que funciona: **o que vemos** (o mundo/categoria como está) → **no que acreditamos** (propósito + valores em comportamento) → **o que fazemos diferente** (posicionamento) → **para quem** (público) → **fecho** (tagline ou promessa). Sem clichê de categoria ("transformar", "revolucionar", "paixão"); sem promessa fora de §3; sem número sem ficha.

## 7. Tagline

3–7 palavras, sobrevive a um ano de uso em todos os contextos de §4. Teste: (a) diz algo que o concorrente mapeado não diria; (b) rastreia à promessa ou ao posicionamento; (c) funciona sem o logo ao lado; (d) não depende de trocadilho que envelhece. Entregar **3–5 opções** ranqueadas com o teste aplicado.

## 8. Glossário

| Termo que usamos | Em vez de | Grafia fixa | Por quê |
|---|---|---|---|

Inclui nomes de produtos exatamente como na arquitetura, termos da categoria que a marca adota ou recusa, anglicismos permitidos/proibidos, tratamento (você/tu/senhor), emojis (se/quais/quando).

## 9. Naming

Nome novo só **dentro do sistema** de arquitetura (padrão, hierarquia, proibições). Processo: brief (papel do que está sendo nomeado, público, o que precisa comunicar) → 15–30 candidatos por rota (descritivo, evocativo, inventado, composto) → filtro do checklist de nome novo (cabe no padrão · não colide com concorrente · pronunciável · domínio/handle) → 3–5 finalistas com racional → arquiteto valida no sistema → strategist/usuário escolhem. Exceção ao sistema só por escrito do arquiteto.
